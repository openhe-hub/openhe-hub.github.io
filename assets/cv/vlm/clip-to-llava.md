## 第 1 章 CLIP:提供零件的那个

> Radford et al., *Learning Transferable Visual Models From Natural Language Supervision*, ICML 2021, OpenAI

### 1.1 要解决什么问题

2021 年之前视觉模型的标准做法是 ImageNet 有监督预训练,问题在于**类别是封闭的**:模型只认识那 1000 个类,加一个新类别就得重新标注、重新训练。而标注成本极高。

CLIP 的赌注:**互联网上天然存在海量图-文配对(alt-text、caption、周边文字),这是免费的、开放词表的监督信号。**

数据集 **WIT-400M**(4 亿图文对),按 50 万个 query 做平衡采样。

### 1.2 结构:极简双塔

```
   Image ──► Image Encoder ──► 线性投影 ──► L2 归一化 ──► x_i ∈ R^d
             (ViT 或 ResNet)

   Text  ──► Text Encoder  ──► 线性投影 ──► L2 归一化 ──► y_j ∈ R^d
             (Transformer, 取 [EOS] 位置的输出)
```

- 文本塔:12 层、512 宽、8 头,BPE 词表 49152,序列截断到 **76 token**
  → 这是 CLIP 一个知名短板:**处理不了长文本**
- 归一化后点积 = 余弦相似度
- **图文之间完全没有交互** → 这就是「零件属性」的来源:图像塔可以单独拆下来用

### 1.3 损失:对称 InfoNCE(重点)

$$
\mathcal{L} = -\frac{1}{2N}\sum_i \Big[ \underbrace{\log \frac{e^{t\,x_i \cdot y_i}}{\sum_j e^{t\,x_i \cdot y_j}}}_{\text{图找文:按行 softmax}} + \underbrace{\log \frac{e^{t\,x_i \cdot y_i}}{\sum_j e^{t\,x_j \cdot y_i}}}_{\text{文找图:按列 softmax}} \Big]
$$

#### 符号

| 符号 | 含义 |
|---|---|
| $x_i$ | 第 i 张图的 embedding,已 L2 归一化 |
| $y_j$ | 第 j 句文本的 embedding,已 L2 归一化 |
| $x_i \cdot y_j$ | 余弦相似度 ∈ [-1, 1] |
| $t$ | 可学习温度(logit scale),把范围拉伸到 [-t, t] |

logits 矩阵 $S_{ij} = t\,(x_i \cdot y_j)$,**对角线是正样本**:

```
              y₁   y₂   y₃   y₄        ← 文本
        x₁ [  ■    □    □    □  ] ─┐
        x₂ [  □    ■    □    □  ]  │ 按行 softmax = 第一项
        x₃ [  □    □    ■    □  ]  │ 「给定图 i,是哪句话?」
        x₄ [  □    □    □    ■  ] ─┘
              │    │    │    │
              └────┴────┴────┴─── 按列 softmax = 第二项
                                   「给定文 j,是哪张图?」
```

#### 它就是一个 N 分类交叉熵

```python
logits = image_emb @ text_emb.T * logit_scale   # [N, N]
labels = torch.arange(N)                        # 标签就是 0,1,2,...,N-1
loss = (F.cross_entropy(logits, labels) +       # 按行
        F.cross_entropy(logits.T, labels)) / 2  # 按列
```

**最妙的是 `labels = arange(N)`**:不需要任何人工标注,「谁和谁配对」这个信息**天然编码在 batch 的下标顺序里**。这是 CLIP 能吃 4 亿数据的根本原因——监督信号免费。

同时:一个 batch 提供 **N 个正样本 + N²−N 个负样本**,负样本数量随 batch 平方增长,几乎白送。

#### 为什么必须要两项?

softmax 是**非对称**的,行归一化和列归一化是两件不同的事。只做一个方向会漏掉一类退化解:

```
假设只优化图→文(按行)
考虑一个「万人迷」图像 x_h,它和所有文本都很像

第 h 行:  y_h 必须打败其他 y  →  这一行约束了它 ✓
其他行:   行是按图像索引的,x_h 根本不出现在别的行里
          → 没有任何一项在惩罚 x_h 与 y_j (j≠h) 的高相似度 ✗
```

这是检索里的 **hub 问题**。加上列方向后,$x_h$ 会出现在每一列的分母里被压下去。

> 一句话:**行约束「每张图的文本排序」,列约束「每句文的图像排序」,两者互不蕴含。**

#### 温度 t 在干什么

| | 行为 | 后果 |
|---|---|---|
| t 大(温度低) | 分布尖锐,概率集中在最像的那个负样本 | 死磕 hard negative,判别力强,但对噪声敏感 |
| t 小(温度高) | 分布平坦,所有负样本权重接近 | 温和,但区分度不足 |

CLIP 把它作为**可学习参数**(以 log t 形式参数化,初始对应 0.07,clamp 上限 100),省掉一个难调的超参。实际训练中它会自己涨到接近上限——**模型主动选择了尖锐**。

#### 梯度视角:softmax 自带 hard negative 挖掘

设 $p_{ij} = \mathrm{softmax}(S_{i,:})_j$:

$$
\frac{\partial \mathcal{L}_i}{\partial S_{ij}} = p_{ij} - \mathbb{1}[i=j]
$$

- **正样本** j=i:梯度 $p_{ii}-1 < 0$ → 推高 → 拉近
- **负样本** j≠i:梯度 $p_{ij} > 0$ → 压低,**力度正比于 $p_{ij}$**

第二条是关键:**越像的负样本被推得越狠,完全自动**,不需要显式 mining。

而且 $\sum_j p_{ij} = 1$ ——**一整行的「推力预算」恒为 1**,负样本之间在抢配额。这是 softmax 的耦合本质,也正是 SigLIP 要拆掉的东西。

#### 名字里的 Info

InfoNCE 出自 CPC(van den Oord et al., 2018),是互信息的一个下界:

$$
I(X;Y) \geq \log N - \mathcal{L}_{\text{InfoNCE}}
$$

界被 $\log N$ 卡住 → 这曾是「batch 必须大」的理论依据。但 SigLIP 的实验削弱了它(见 3.4)。

### 1.4 一个被低估的消融:12× 效率差

| 训练目标 | 达到同等 zero-shot 效果所需算力 |
|---|---|
| Transformer 自回归预测 caption 原文 | 1× (基准) |
| 词袋预测(不管顺序) | **3× 更快** |
| **对比学习** | **12× 更快** |

**结论:逐字预测 caption 是一个太难也太浪费的任务。** 同一张图有无数种合法描述,强迫模型精确复现某一种,大量算力被消耗在学习语言的表层变体上。对比学习只要求「能区分开」,难度骤降、信号密度骤升。

这个 12× 是 CLIP 能吃下 4 亿数据的直接原因。

### 1.5 Zero-shot 怎么做到的

把分类问题重写成检索问题:

```
类别名 → 填模板 → "a photo of a {dog}."  ──► 文本塔 ──► 权重向量
                   "a photo of a {cat}."  ──► 文本塔 ──► 权重向量
                                                          ...
      待分类图片 ──► 图像塔 ──► 与所有类向量算相似度 → argmax
```

等价于**用文本塔临时合成了一个分类头**。换类别?换句话就行,零训练。

两个工程技巧:
- **Prompt engineering**:"dog" 不如 "a photo of a dog." ——训练数据里几乎都是完整句子,单个词属于分布外
- **Prompt ensembling**:80 个模板分别编码后**在归一化前平均**,ImageNet 再涨约 3.5%

结果:zero-shot ImageNet **76.2%**,持平有监督 ResNet-50。更震撼的是 ImageNet-Sketch / -A / -R 等**分布偏移**测试集上大幅碾压有监督模型——说明学到的不是数据集捷径特征。

### 1.6 CLIP 的痛点(SigLIP 的入口)

softmax 需要**全局归一化**:

```
分布式训练时:
  ① 必须 all-gather 所有设备的 embedding 才能算分母
  ② 要在内存里物化 N×N 相似度矩阵,N=32768 时是 10 亿个数
  ③ 行归一化、列归一化各算一遍
  ④ batch size 与损失函数强耦合 —— 小 batch 训不好
```

内存 **O(N²)**,通信开销巨大。想训 CLIP,你先得有一大堆卡。

另一个坑:**假负样本(false negative)**。32768 张图里必然有好几张都是「草地上的狗」,配的文本也几乎一样,却被强行推开。ALBEF/BLIP 用动量编码器 + 软标签来缓解。

## 第 2 章 BLIP:统一理解与生成

> Li et al., *BLIP: Bootstrapping Language-Image Pre-training for Unified Vision-Language Understanding and Generation*, ICML 2022, Salesforce

两大贡献:**MED 架构**(模型侧)+ **CapFilt**(数据侧)。

### 2.1 贡献一:MED —— 一套参数,三种人格

Multimodal mixture of Encoder-Decoder。核心动机:ITC / ITM / LM 三个任务需要的网络行为差异其实很小,只在**自注意力的掩码方式**和**是否接入图像**上不同。

```
                         ┌──────────────┐
       Image ──────────► │  ViT (共享)  │ ──┬──► [CLS]_img ──► ITC
                         └──────────────┘   │
                                            │ (patch tokens 作为 K,V)
   ┌────────────────────────────────────────┴────────────────┐
   │                          │                               │
   ▼                          ▼                               ▼
┌─────────┐            ┌─────────────┐              ┌──────────────┐
│ 模式 ①  │            │   模式 ②    │              │    模式 ③    │
│ 文本编码│            │ 图像引导编码│              │ 图像引导解码 │
├─────────┤            ├─────────────┤              ├──────────────┤
│ Bi-SA   │            │   Bi-SA     │              │  Causal-SA   │◄── 唯一不共享
│ (无 CA) │            │     CA      │              │      CA      │
│  FFN    │            │    FFN      │              │     FFN      │
└────┬────┘            └──────┬──────┘              └──────┬───────┘
   [CLS]                  [Encode]                     [Decode]
     │                        │                            │
    ITC                      ITM                          LM
```

三种模式各有一个**任务专属起始 token**(`[CLS]` / `[Encode]` / `[Decode]`),等于告诉模型「现在执行哪个任务」。文本侧由 BERT-base 初始化。

#### 前置概念:SA 与 CA

| | Query | Key / Value | 作用 |
|---|---|---|---|
| **SA**(自注意力) | 文本 token | 文本 token | 文本内部互相看,建模句子自身结构 |
| **CA**(交叉注意力) | 文本 token | 图像 patch | 文本去「查询」图像,注入视觉信息 |

CA 里 Q 和 K/V 长度可以不等(30 个 text token 去看 577 个 image patch 完全没问题),这正是它能跨模态的原因。

#### 模式 ①:单模态文本编码器 → ITC

图文各自独立编码,`[CLS]` 输出做对比学习,和 CLIP 一样。沿用 ALBEF 的两个改进:
- **动量编码器 + 队列**(EMA 系数 0.995)提供更多负样本
- **软标签**:动量模型的相似度分布作为 soft target,缓解假负样本问题

ITC 的作用是**在融合之前先把两个模态的特征空间对齐**,后面 CA 的学习会容易得多。

#### 模式 ②:图像引导的文本编码器 → ITM

在每个 block 的 SA 与 FFN **之间**插入一层 CA:

```
        text tokens
             │
    ┌────────▼────────┐
    │  Bi Self-Attn   │   Q=K=V= text
    └────────┬────────┘
    ┌────────▼────────┐
    │  Cross-Attn     │   Q = text,  K=V = image patches   ← 新增
    └────────┬────────┘
    ┌────────▼────────┐
    │      FFN        │
    └─────────────────┘
```

`[Encode]` 输出接线性头做二分类。**Hard negative mining** 是关键:负样本按 ITC 相似度加权采样,越「像」的错误配对越可能被选中,逼迫 ITM 学细粒度对齐(「男人骑马」vs「马骑男人」)。

> ITC 粗筛,ITM 精判 —— 二者互补,下游检索时也是这个两阶段流程。

#### 模式 ③:图像引导的文本解码器 → LM

结构与模式 ② **完全相同**,只把双向 SA 换成因果 SA(改一个 attention mask),自回归预测下一个 token,交叉熵 + label smoothing 0.1。

**为什么用 LM 而非 MLM?** 多数 VLP 工作(ALBEF、VLBERT)用 MLM,但 MLM 无法直接生成。LM 让模型天然具备把视觉信息转成连贯文本的能力,这正是 CapFilt 里 Captioner 的基础。

### 2.2 关键理解:为什么有的双向、有的因果

**判据只有一句话:这段文本是「输入」,还是「要被产出的输出」?**

```
任务想干什么  →  文本是输入还是输出  →  能不能看全文  →  用什么 mask
```

⚠️ 注意因果方向:**可见性是结果,不是原因**。记成「因为看不全所以是 LM」,遇到新模型就会推错。

**理解任务(ITC/ITM):文本是输入,完整给定**

```
"一个男人 在 骑 马"
   编码「骑」时:← 左边有「男人」(施动者),→ 右边有「马」(受动者)
```
全文可见,让每个 token 看到全文编码质量更高。强加因果 mask 只会白白损失信息。这就是 BERT 相对 GPT 在理解任务上的优势来源。

**生成任务(LM):文本是输出,必须逐个吐出**

```
step 1:  [Decode] → "一个"
step 2:  [Decode] 一个 → "男人"
step 3:  [Decode] 一个 男人 → "在"
```
第 3 步时「骑马」在宇宙中还不存在。所以模型学到的能力必须是「只依赖左边」,否则训练学的本领推理时用不上。

**真正的坑在训练阶段。** 训练时为了效率把整句并行送入(teacher forcing):

```
输入:  [Decode] 一个 男人 在 骑 马
目标:    一个    男人  在 骑 马 [EOS]
                        ↑
              位置 3 要预测「骑」,但「骑」就在输入里!
```

不加 mask,模型会学到平凡解——**抄答案**。loss 瞬间归零,推理时输出垃圾。

> **因果 mask 的本质:用一次并行前向,模拟出 n 次串行生成的效果,同时堵死信息泄漏。**

```
Bi-SA (双向)          Causal-SA (因果)
   a b c d               a b c d
a  ✓ ✓ ✓ ✓           a  ✓ ✗ ✗ ✗
b  ✓ ✓ ✓ ✓           b  ✓ ✓ ✗ ✗
c  ✓ ✓ ✓ ✓           c  ✓ ✓ ✓ ✗
d  ✓ ✓ ✓ ✓           d  ✓ ✓ ✓ ✓
```

**推论**:图像那边的 ViT **永远是双向的**,从不加因果 mask。因为 patch 没有「顺序」概念,也不需要被自回归生成。
→ **因果性来自「生成」这个动作,不来自「模态」。**

### 2.3 参数共享:为什么只有 SA 不共享

| 共享方式 | 结果 |
|---|---|
| 全部共享(含 SA) | 明显变差 |
| **除 SA 外全共享** | **最优** |
| 完全不共享 | 参数翻倍,性能无提升 |

- **SA 层**承载编码/解码的本质差异:一个是「为所有 token 构建双向表征」,一个是「根据前文预测下一个」。信息流动方式天然对立,强行共享会任务冲突。
- **Embedding / CA / FFN** 在两任务里功能相似(注入图像、通道混合),共享既省参数又相当于多任务正则。

代价:每个图文对需要 **1 次 ViT 前向 + 3 次文本 transformer 前向**。文本侧比 ViT 轻,整体可接受。

$$
\mathcal{L} = \mathcal{L}_{\text{ITC}} + \mathcal{L}_{\text{ITM}} + \mathcal{L}_{\text{LM}}
$$

### 2.4 三个任务的横向对比(重要)

| | ITC | ITM | LM |
|---|---|---|---|
| 问的问题 | batch 内谁配谁? | 就这一对,配不配? | 给图,把它描述出来 |
| 判别 or 生成 | 判别 | 判别 | **生成** |
| 图文交互 | 无(**双塔**) | 深度(**单塔**,CA) | 深度(CA) |
| 文本角色 | 输入 | 输入 | **输出** |
| SA mask | 双向 | 双向 | **因果** |
| 优点 | 向量可预计算,毫秒级检索全库 | 抓细粒度对齐 | 唯一能产出文本 |
| 缺点 | 一个向量装不下细节 | N 张图要跑 N 次前向 | — |
| 下游 | 粗排检索 | 精排检索、NLVR2 | Caption、VQA |

**看这张表,「生成」那一列整个是与众不同的**——不只是 mask 不同,是它做的事根本不是一类。BLIP 的野心是把这两类塞进一套参数,答案是:**冲突只发生在 SA 层,那就只把 SA 拆开。**

### 2.5 贡献二:CapFilt —— 模型自己给自己造数据

#### 问题有多严重

alt-text 的本职工作是 SEO 和无障碍访问,**不是描述图像内容**:

```
图:一只金毛在草地上叼飞盘
alt:"DSC_0472.jpg"
alt:"点击查看大图 | 宠物用品店 | 全场包邮"
alt:"Golden Retriever"           ← 有信息但极度稀疏
```

过去的做法是「数据量大就行,噪声会被平均掉」。BLIP 说:噪声可以主动清理,而清理工具就是模型自己。

#### 完整流程

```
       ┌─────────────────────────────────────────────┐
       │  Step 0: 用 噪声网络数据 + 人工数据          │
       │          预训练一个 MED  (ITC+ITM+LM)        │
       └──────────────────┬──────────────────────────┘
                          │  拆成两半,各自在 COCO 上微调
              ┌───────────┴───────────┐
              ▼                       ▼
      ┌───────────────┐       ┌───────────────┐
      │  Captioner    │       │    Filter     │
      │  = 模式③解码器 │       │ = 模式①②编码器│
      │  LM 微调       │       │ ITC+ITM 微调   │
      └───────┬───────┘       └───────┬───────┘
              │                       │
      Iw ─────┤                       │
              ▼                       ▼
            Ts (合成描述)      判定 Tw / Ts 是否匹配
                                      │
       ┌──────────────────────────────┴──────────┐
       │  新数据集 D' =                            │
       │    过滤后的 (Iw,Tw)                       │
       │  + 过滤后的 (Iw,Ts)   ← 同一张图可保留两条 │
       │  + 人工的  (Ih,Th)                        │
       └──────────────────┬───────────────────────┘
                          ▼
              重新 from scratch 预训练一个新模型
```

容易看漏的四个点:

1. **Captioner 和 Filter 来自同一个预训练模型**,只是分别取 MED 的不同「人格」微调。这是 MED 三模式设计的回报:一次预训练,白送两个专用工具。
2. **Filter 的判据就是 ITM 头**。且 **Tw 和 Ts 一视同仁地过滤**,不因为 Ts 是自己生成的就网开一面。
3. **一张图可能同时保留 Tw 和 Ts 两条**,所以数据量可能**增加**。CapFilt 不是单纯的减法。
4. **最后是从零重训,不是继续微调**——让新模型完全生长在干净数据上。也因此论文里 CapFilt **只做了一轮**。

#### 消融:两个部件缺一不可

| 配置 | 效果 |
|---|---|
| baseline(原始噪声数据) | — |
| 只加 Filter | 有提升 |
| 只加 Captioner | 有提升 |
| **Cap + Filt** | **提升最大** |

因为两者做的是**正交**的事:

- **Filter 是减法**:去掉错误监督信号,提升数据**精度**
- **Captioner 是加法**:凭空造出高质量描述,提升数据**信息量**

只过滤的话,那些「图很好但 alt-text 是 DSC_0472.jpg」的样本会被整条扔掉,**图像本身的价值也一起浪费**。Captioner 救回了这批图。反过来只加 caption 不过滤,生成器的幻觉会污染数据。

提升在 14M → 129M 数据、ViT-B → ViT-L 模型上都保持,说明不是小数据集上的技巧。

#### 反直觉发现:nucleus sampling > beam search

| 解码方式 | 被 Filter 判为噪声的比例 | 下游性能 |
|---|---|---|
| Beam search | 更低(约 19%) | 较差 |
| **Nucleus sampling** | 更高(约 25%) | **更好** |

原因:beam search 在做**最大似然搜索**,会收敛到数据集里最高频、最模板化的说法——

```
"a man riding a horse on a beach"
"a man riding a bike on a street"
"a woman walking on a beach"
   ↑ 句式几乎复制粘贴,信息熵极低
```

这些句子模型早就会说了,**学不到新东西**。随机采样吐出更长尾、更具体的表述,虽然错得更多,但正确的那部分携带了模型原本不具备的信息。

> **元教训:自训练/伪标签场景下,「标签的正确率」不是唯一指标,「标签的信息增益」同样重要。** 过度追求置信度会让自蒸馏退化成自我复读。这在后来的 model collapse 讨论里被反复验证。

#### 为什么 Captioner 和 Filter 不能共享参数

论文专门做了消融,共享会掉点。原因是**确认偏误(confirmation bias)**:

```
共享参数时:
   Captioner 生成「一只猫在弹钢琴」(幻觉)
   Filter 用同一套权重判断 → 「嗯,这正是我会说的话,匹配!」
   → 幻觉全部通过,过滤形同虚设
```

判别器必须保持独立性才有意义。同 GAN 里生成器判别器分开、集成学习追求 base learner 多样性。

### 2.6 自举为什么能成立?(核心洞察)

**问题:模型是从脏数据里学出来的,凭什么它能反过来判断这批数据的对错?这不是循环论证吗?**

答案:

> **噪声是随机的,信号是系统的。**

一亿条数据里 alt-text 的错法五花八门(文件名、广告、无关关键词),但「狗长什么样」在千万张狗图里是**一致重复**的。梯度下降本质在做统计平均——**一致的信号被累积放大,随机的噪声互相抵消**。

于是训练完的模型,其质量**高于**训练它的那批数据的平均质量。这个差值就是台阶的高度。

```
数据平均质量  ────────────  60 分
                              ↑ 泛化把随机噪声平均掉了
模型判断能力  ────────────  75 分
                              ↑ 用 75 分的模型清洗 60 分的数据
清洗后数据    ────────────  70 分
                              ↑ 再训
新模型        ────────────  80 分
```

**但第二轮就没那么灵了。** 数据已被清洗,残留错误不再是随机噪声,而是模型自己的**系统性偏差**(COCO 风格的短句偏好、对长尾概念的忽视)。系统性偏差没法靠平均消除,模型看不见自己的盲区。台阶到这里踩空。

这解释了为什么后来的做法是**换一个盲区不同的外部更强模型来 recaption**(GPT-4V、更大的 VLM),而不是让同一个模型反复自举。也解释了 BLIP 为什么保守地只滚一轮:成本高、收益递减、且误差累积会导致 **model collapse**——雪球滚着滚着可能滚成一个越来越圆滑、越来越空洞的球。

### 2.7 CapFilt 的后世影响

- **LAION-COCO**(600M 合成 caption 数据集)就是用 BLIP 的 captioner 批量生成的
- 现在几乎所有 VLM 数据流水线都有 recaption 环节(LLaVA、ShareGPT4V、DALL-E 3)
- DALL-E 3 技术报告的核心结论「训练一个好的图像 captioner 来重写数据集」与 CapFilt 完全同源

局限:Captioner 和 Filter 都在 COCO 上微调,会把 **COCO 的域偏好**(短句、日常物体、特定标注风格)注入整个网络数据,长尾概念反而可能被抹平。

## 第 3 章 SigLIP:把损失函数解耦

> Zhai et al., *Sigmoid Loss for Language Image Pre-Training*, ICCV 2023, Google DeepMind

### 3.1 核心改动:一行公式

**把「从 N 个候选里选一个」改成「对每一对独立判断是/否」。**

$$
\mathcal{L} = -\frac{1}{N}\sum_{i}\sum_{j} \log \frac{1}{1 + e^{\,z_{ij}(-t\,x_i \cdot y_j + b)}}, \qquad z_{ij} = \begin{cases} +1 & i = j \\ -1 & i \neq j \end{cases}
$$

```
Softmax (CLIP)                    Sigmoid (SigLIP)
┌─────────────────┐               ┌─────────────────┐
│ ■ □ □ □         │               │ ■ □ □ □         │
│ □ ■ □ □   ← 整行竞争             │ □ ■ □ □   每格独立│
│ □ □ ■ □     分母耦合             │ □ □ ■ □   互不影响│
│ □ □ □ ■         │               │ □ □ □ ■         │
└─────────────────┘               └─────────────────┘
  每个元素的梯度                     每个元素的梯度
  依赖同行/同列所有元素               只依赖它自己
```

**解耦是全部收益的来源。**

### 3.2 那个 bias 项不是可有可无的

$b$ 初始化为 **−10**(温度 $t$ 初始为 10)。这是必须的:

N×N 矩阵里正样本 N 个,负样本 **N²−N** 个。N=16k 时正负比是 **1 : 16383**。不加负偏置的话,初始时模型对所有对输出中性预测,海量负样本的梯度会把所有 embedding 无差别推开,训练早期严重不稳定。

$b=-10$ 相当于说:**先默认所有对都不匹配**,再慢慢把对角线拉起来。同目标检测里 focal loss 处理前景/背景极度不平衡时的偏置初始化。

### 3.3 实现:从 O(N²) 到 O(b²)

没有全局归一化 → 损失可以**分块累加**。论文的 chunked 实现是个环状传递:

```
D 个设备,每个持有 b = N/D 个样本

Step 1:  设备1 [img₁ × txt₁]   设备2 [img₂ × txt₂]   设备3 [img₃ × txt₃]
                    ↓ 文本表示沿环传给下一个设备 ↓
Step 2:  设备1 [img₁ × txt₃]   设备2 [img₂ × txt₁]   设备3 [img₃ × txt₂]
                    ↓
Step 3:  设备1 [img₁ × txt₂]   设备2 [img₂ × txt₃]   设备3 [img₃ × txt₁]

D 步之后所有 N² 对都算过了,
但任何时刻单卡上只有 b×b 的小块。
```

- 单卡峰值内存 **O(N²/D²)** 而非 O(N²)
- 通信量:每步只传 b 个向量,而非 all-gather 全部
- 只需算一遍(sigmoid 天然对称,没有行/列之分)

论文里这个实现能在 **4 块 TPUv4 上两天训出 84.5% ImageNet zero-shot** 的 SigLiT。

### 3.4 最反直觉的实验结论

社区当时的共识是「对比学习 batch 越大越好」。SigLIP 一直测到 **batch size = 1M**:

```
性能
  │                    ┌──────────────────  sigmoid
  │                ╱───┘
  │            ╱───────────────────────────  softmax
  │        ╱ ╱
  │    ╱  ╱
  │  ╱ ╱
  └──┴────┴────┴────┴────┴────┴──► batch size
    4k   8k  16k  32k  128k  1M
     ↑              ↑
  sigmoid       性能基本饱和
  优势最大       再大收益极小
```

1. **小 batch 下 sigmoid 明显更优**(< 16k 时优势显著)。softmax 在小 batch 下负样本太少,归一化项估计不准;sigmoid 没有这个依赖。
2. **32k 左右就饱和了**,推到 1M 几乎没有额外收益 → 终结了「堆 batch size」的军备竞赛,也削弱了 InfoNCE 的 $\log N$ 理论论证:**理论上界的增长 ≠ 实际表征质量的增长**。

**对普通研究者意义巨大**:从「必须有几百块卡才能训 CLIP」变成「几块卡也能训一个像样的图文模型」。

另外 sigmoid 对**数据噪声更鲁棒**:softmax 里一个错误的高分负样本会挤压整行分母、扭曲所有梯度;sigmoid 里它只影响自己那一格。

### 3.5 SigLIP 2(2025 年初)

在原配方上叠加:

- **多语言**:WebLI 多语种数据,不再英文专用
- **加入解码器目标**(LocCa 式的 captioning / referring expression),弥补纯对比学习**空间定位能力弱**的老毛病
- **自蒸馏 + 掩码预测**(SILC/TIPS 路线),显著改善**稠密特征**质量 → 分割、深度估计受益
- **NaFlex 变体**:支持原生长宽比和可变分辨率,不再强行方形 resize
- 尺寸:ViT-B / L / **So400m** / g

其中 **So400m**(shape-optimized 400M)是今天用得最多的一档,通过对 ViT 宽度/深度做形状搜索得到,同等算力下性价比最高。

## 第 4 章 BLIP-2 与 Q-Former:一座桥

> Li et al., *BLIP-2: Bootstrapping Language-Image Pre-training with Frozen Image Encoders and Large Language Models*, ICML 2023

### 4.1 动机:别再从头训了

BLIP 的 MED 是端到端全参数训练。到 2023 年这条路走不通:视觉侧已有 CLIP ViT-L / EVA-CLIP ViT-g,语言侧已有 OPT / FlanT5,重训一遍既烧钱又打不过。

策略变成:**两头都冻住,只训中间那一小块。** 但立刻撞上硬问题:

```
   ❄冻结的 ViT ─────►  [257 个 patch 向量]   ???   ❄冻结的 LLM
                        纯视觉空间                   只认 token embedding
                                    ↑
                            模态鸿沟 (modality gap)
                        LLM 这辈子没见过图像特征
```

LLM 冻了没法适应视觉特征,ViT 冻了没法迎合 LLM。**只能在中间插一个可训练的翻译官。**

### 4.2 结构

```
                    ┌──────────── Q-Former (188M, BERT-base 初始化) ────────────┐
                    │                                                          │
  32 个可学习 Query │  ┌────────────────────────────────────────────┐          │
  (32 × 768)  ──────┼─►│  Self-Attention   ← 共享层,Query 与文本共用 │          │
                    │  └──────────────────┬─────────────────────────┘          │
  ❄ViT 输出         │  ┌──────────────────▼─────────────────────────┐          │
  (257 × 1024) ─────┼─►│  Cross-Attention  ← 每隔一层插入,仅 Query 走│          │
                    │  └──────────────────┬─────────────────────────┘          │
                    │  ┌──────────────────▼─────────────────────────┐          │
                    │  │       FFN (图像分支 / 文本分支各一套)        │          │
                    │  └────────────────────────────────────────────┘          │
                    │                    × 12 层                                │
                    └───────────────────────┬──────────────────────────────────┘
                                            ▼  输出 32 × 768
```

1. **两个子模块共享 self-attention 层**(一个图像 transformer 处理 query,一个文本 transformer 处理文本)。共享 SA 是让 query 和文本能在同一层交互的机制——**设计哲学与 MED 一脉相承,只是共享/不共享的边界重画了**。
2. **Cross-attention 只有 query 分支有**,每隔一个 block 插一次,随机初始化。文本 token **永远看不到图像**。
3. **输出 32×768,远小于输入 257×1024** —— 这个压缩不是副作用,是核心设计。

### 4.3 Query 到底是什么

就是 32 个随机初始化的向量,和 `nn.Parameter` 里的普通权重没区别,跟着梯度下降学。**不依赖输入**——无论来什么图,进去的都是这同样 32 个向量。

关键在于它们在 cross-attention 里充当 **Query**:

$$
\text{CA}(Q,K,V):\quad Q = \text{32 个可学习向量},\quad K,V = \text{257 个图像 patch}
$$

可以理解成 **32 个学出来的「提问槽位」**:

```
query₁: "画面里主体是什么?"        ──► 去 257 个 patch 里检索答案
query₂: "在什么场景/背景?"          ──► 去检索
query₃: "有什么动作正在发生?"       ──► 去检索
...
```
(真实 query 没这么可解释,但功能上就是**每个 query 学会关注一类视觉信息**。)

**同类范式**(统称 learnable query / resampler,本质是把变长冗余输入压成定长紧凑表示):
- **DETR 的 object query** —— 100 个可学习向量,每个负责「捞」一个物体
- **Perceiver 的 latent array**
- **Flamingo 的 Perceiver Resampler** —— 与 Q-Former 几乎同期的同类物

### 4.4 阶段一:表示学习

只用 Q-Former + ❄ViT 训,**还不接 LLM**。又是 ITC / ITM / 生成三件套,但这次 **mask 控制的是 query 与 text 之间能不能互相看**:

| 任务 | mask 设计 | 为什么 |
|---|---|---|
| **ITC** | Query ─╳─ Text(互不可见) | **防信息泄漏**:query 若能看到配对文本,直接抄进表征,对比学习变成平凡解 |
| **ITG** | Query↔Query 可见;Query ─╳→ Text;Text → Query 可见;Text 内部因果 | 见下 |
| **ITM** | Query ↔ Text 全可见 | 深度融合做二分类,hard negative mining |

**ITC 实现细节**:输出是 32 个 query 向量,文本只有一个 `[CLS]` → **分别算 32 个相似度取最大值**。
**ITM 实现细节**:每个 query 输出接二分类头,**32 个 logits 取平均**。

**ITG 的 mask 设计非常精妙,值得停下来品:**

> **文本要生成 caption,但它接触不到图像,只能通过 32 个 query。**

于是形成**信息瓶颈的强制压力**:query 必须把生成文本所需的全部视觉信息榨取出来,否则解码器写不出来。这是训练 query 的核心驱动力。

(BLIP 里叫 LM,这里改叫 ITG = Image-grounded Text Generation,强调「以图为条件」。)

**MED vs Q-Former 的 mask 策略对比:**

| | MED (BLIP) | Q-Former (BLIP-2) |
|---|---|---|
| mask 控制什么 | 文本内部的 SA 方向 | **query 与 text 之间的可见性** |
| 图像怎么进来 | 文本经 CA 看图 | **只有 query 经 CA 看图** |
| 不共享的部分 | SA 层 | 共享 SA,FFN 分两套 |

### 4.5 阶段二:接上 LLM

```
  Image ──► ❄ViT ──► 🔥Q-Former ──► 32×768 ──► 🔥FC线性层 ──► 32 个"软视觉 token"
                                                                    │
                        文本 token embedding ──► [v₁...v₃₂, t₁ t₂ t₃ ...] ──► ❄LLM
                                                  ↑
                                            拼在最前面当前缀
```

就是一个**线性投影**把 768 映射到 LLM 的 embedding 维度,当作 **soft visual prompt** 前置。训练只有 Q-Former + FC 在动。

- **Decoder-only(OPT)**:标准 LM loss
- **Encoder-decoder(FlanT5)**:prefix LM loss,文本切成前缀送 encoder(与视觉 token 拼一起),后缀交给 decoder 生成

### 4.6 为什么必须两阶段

关键消融:**跳过阶段一直接做阶段二,性能大幅下滑,训练还不稳定。**

```
没有阶段一:
  query 是随机的 → 输出的 32 个向量是视觉噪声
  → LLM 冻结无法适应噪声 → 只能靠 LM loss 这个极弱信号反推
  → 学得慢、学不好,甚至灾难性遗忘(LLM 开始输出乱码)

有阶段一:
  query 已学会「提取与语言相关的视觉信息」
  → 阶段二只需学「怎么把这些信息翻译成 LLM 的方言」
```

> **阶段一 = 让 query 先学会「该看什么」;阶段二 = 「怎么说给 LLM 听」。** 两个难题拆开各个击破。

### 4.7 成绩与局限

BLIP-2 (ViT-g + FlanT5-XXL) 在 zero-shot VQAv2 上超过 **Flamingo-80B 约 8.7 个点,可训练参数少 54 倍**。

证明了:**你不需要训一个 80B 的巨兽,只需要训好中间那座桥。**

局限(论文自己承认):
- **in-context learning 能力弱**——预训练时每样本只有一张图,没学过多图上下文(Flamingo 的交错图文数据在这点上更强)
- 继承 LLM 的所有毛病:幻觉、有害输出、知识过时

## 第 5 章 LLaVA:桥为什么可以变笨

### 5.1 LLaVA 做了什么

几乎同期(2023 年 4 月),LLaVA 做了一件极其朴素的事:

```
❄CLIP ViT ──► 576 个 patch ──► 一个线性层(后来是 2 层 MLP) ──► 576 个 token ──► 🔥LLM
                                      ↑
                            没有 query,没有阶段一,不压缩
```

结果这条路线赢了。今天 LLaVA 系、Qwen2-VL、InternVL、PaliGemma 的连接器基本都是 MLP 或简单 patch-merge。

### 5.2 但真正的原因不是 MLP 本身

**关键洞察:**

> **连接器的复杂度,与 LLM 被冻结的程度成正比。**

| | BLIP-2 | LLaVA |
|---|---|---|
| ViT | ❄ 冻 | ❄ 冻 |
| 连接器 | 🔥 Q-Former (188M) | 🔥 MLP (~20M) |
| **LLM** | **❄ 全程冻死** | **🔥 第二阶段解冻** |

BLIP-2 的卖点就是「LLM 一个参数都不动」→ LLM 完全不会向视觉侧靠拢一步,**适配的全部负担压在桥上**。桥必须自己学会说 LLM 的方言,还得说得极标准。那当然要 188M 参数、两阶段、三个损失。

LLaVA 让 LLM 自己动 → 连接器只需把视觉特征扔进 LLM 输入空间大致对齐,剩下 LLM 会自己学着理解。它有 7B 参数,吸收一点奇怪的输入分布毫无压力。

```
LLM 冻死  →  桥必须很聪明  →  Q-Former
LLM 能动  →  桥可以很笨    →  一个线性层就够
```

**不是「Q-Former 走了弯路」,是「约束不同,最优解不同」。**

### 5.3 2023 年初为什么非要冻 LLM

三个真实约束(不要事后诸葛亮):

1. **微调 LLM 当时被认为太贵。** BLIP-2 的核心 pitch 就是「可训练参数比 Flamingo-80B 少 54 倍」,放开 LLM 这个卖点直接归零。
2. **上下文长度。** OPT/FlanT5 上下文只有 2048 甚至更短。576 个视觉 token 要吃掉 **28% 的窗口**,那个年代很奢侈。压到 32 个 token(1.5%)有强烈现实动机。今天动辄 128k,这个压力消失了。
3. **灾难性遗忘的恐惧。** 当时普遍担心用图文数据微调会毁掉 LLM 的语言能力。是指令微调方法论成熟后,大家才发现解冻其实很可控。

### 5.4 LLaVA 真正的贡献:Visual Instruction Tuning

很多人搞反了。论文标题是 **Visual Instruction Tuning**,不是 "Linear Projection is All You Need"。

真正的突破是:**用纯文本的 GPT-4,造出多模态指令数据。**

```
COCO 的标注:  bounding box 坐标 + 5 句 caption(纯文本!)
       │
       ▼  喂给 GPT-4(它看不见图,只看这些文本描述)
       │
   生成三类数据:多轮对话 / 详细描述 / 复杂推理
       │
       ▼
   158K 条视觉指令数据
```

**GPT-4 全程没看过任何一张图**,但通过文本化的场景描述,能造出高质量的「看图对话」。

这与 CapFilt 一脉相承——**用一个强模型给弱监督数据升级**,只是老师换成了外部的、**盲区完全不同**的 LLM(正好呼应 2.6 节说的:自举失效是因为看不见自己的盲区)。

> **顺序是:有了这批数据 → LLM 才有理由被解冻 → 连接器才有资格退化成 MLP。** 不是反过来。

### 5.5 Q-Former 输在哪:32 个 query 是残酷的信息瓶颈

257 个 patch 压成 32 个向量,压缩率 8:1。整体语义(这是一只狗、在草地上)绰绰有余,但:

```
OCR:      图里有 200 个字符 → 32 个向量装不下
细粒度:   「左边第三个人穿什么颜色」→ 空间信息在压缩中丢失
文档理解: 表格、图表 → 全军覆没
```

而 MLP 保留全部 patch,**分辨率一提高 token 数就跟着涨,信息一点不丢**。BLIP-2 在 OCR/文档类任务上的孱弱,根源就在这里。

另外 Q-Former **难训**:两阶段、三损失、随机初始化的 CA、188M 参数,超参敏感、复现困难。MLP 只有两层,几小时训完,而且**几乎调不坏**。

### 5.6 但 resampler 没死

在 **token 数量是硬约束**的地方,压缩仍是刚需:

- **视频**:8 帧 × 576 token = 4608,32 帧就爆了
- **多图对话**:同上
- **长上下文成本**:注意力是 O(n²)

看 Qwen2-VL 的做法:

```
动态分辨率 → patch 数量可变,高清图能到几千个 token
             ↓
        2×2 patch merge(4:1 压缩)   ← 不丢空间结构的压法
             ↓
        送进 LLM
```

> **被淘汰的是「用固定数量的抽象 query 做剧烈压缩」这个具体实现,不是「需要压缩」这个判断。**
> 压缩要付代价:图像单张、分辨率可控时别压;token 会爆炸时压,但尽量用不丢空间结构的压法。

## 第 6 章 贯穿全篇的元规律

### 6.1 简单可扩展 > 精巧有偏置

这个故事在本文里出现了**四次**:

| 场景 | 精巧方 | 简单方 | 谁赢 |
|---|---|---|---|
| 预训练目标 | 自回归预测 caption | 对比学习 | 简单方(快 12×) |
| 模型定位 | BLIP 的 MED 三任务耦合 | CLIP 双塔 | 简单方(能 scale) |
| 对比损失 | softmax 全局归一化 | sigmoid 逐对独立 | 简单方(省内存、小 batch 也行) |
| 连接器 | Q-Former | MLP | 简单方(不丢信息) |
| (番外)视觉主干 | CNN 的归纳偏置 | ViT | 数据一多,简单方赢 |

原理:**数据一多、算力一足,结构简单但不丢信息的方案,会追上并超过结构精巧但有归纳偏置的方案。** 归纳偏置在小数据下是样本效率,在大数据下是枷锁。

### 6.2 数据质量可以被模型自己提升

```
CapFilt (BLIP)          用自己的两个人格互相清洗
   │                    局限:只能滚一轮,看不见自己的盲区
   ▼
LLaVA                   换一个盲区不同的老师(纯文本 GPT-4)
   │
   ▼
DALL-E 3 / ShareGPT4V   用更强的 VLM 全库 recaption
```

成立的前提:**噪声是随机的,信号是系统的** → 模型质量高于训练它的数据的平均质量 → 这个差值就是台阶。
失效的时刻:**残留误差变成系统性偏差** → 平均不掉 → 需要外部老师。

### 6.3 精巧模块的价值取决于周围是不是被锁死

- LLM 冻结 → 需要 Q-Former;LLM 解冻 → MLP 就够
- 上下文短 → 需要激进压缩;上下文长 → 全量塞进去
- 数据少 → 需要归纳偏置;数据多 → 归纳偏置成枷锁

> **下次看到一个复杂设计,先别问「为什么这么绕」,先问「作者当时被什么锁住了」。**

### 6.4 因果性来自「生成」,不来自「模态」

判据永远是:**这段序列是输入,还是要被产出的输出?**
- 输入 → 双向(全文可见,编码质量更高)
- 输出 → 因果(推理时右边不存在;训练时防止抄答案)

ViT 从不加因果 mask,因为 patch 没有顺序、也不需要被自回归生成。

### 6.5 判别 vs 生成、双塔 vs 单塔

| | 双塔(late fusion) | 单塔(early/deep fusion) |
|---|---|---|
| 代表 | CLIP / SigLIP / BLIP-ITC | BLIP-ITM / Q-Former |
| 交互 | 只在最后算相似度 | 逐层 cross-attention |
| 检索复杂度 | 向量可预计算,O(1) 查询 | N 次前向,O(N) |
| 细粒度 | 弱 | 强 |
| 可拆卸性 | **高(能当零件)** | 低 |

实践中的标准答案是**流水线**:双塔粗筛 top-k → 单塔精排。BLIP 的 ITC+ITM 正是这个组合,而且训练时 ITM 的 hard negative 就按 ITC 相似度采样,两者互相喂养。

### A.2 核心公式

**CLIP / InfoNCE**
$$
\mathcal{L} = -\frac{1}{2N}\sum_i \Big[ \log \frac{e^{t\,x_i \cdot y_i}}{\sum_j e^{t\,x_i \cdot y_j}} + \log \frac{e^{t\,x_i \cdot y_i}}{\sum_j e^{t\,x_j \cdot y_i}} \Big]
$$

**梯度**(自带 hard negative 挖掘)
$$
\frac{\partial \mathcal{L}_i}{\partial S_{ij}} = p_{ij} - \mathbb{1}[i=j]
$$

**SigLIP**
$$
\mathcal{L} = -\frac{1}{N}\sum_{i,j} \log \sigma\big(z_{ij}(t\,x_i \cdot y_j - b)\big),\quad z_{ij}=\pm 1,\ b_{\text{init}}=-10
$$

**BLIP 总损失**
$$
\mathcal{L} = \mathcal{L}_{\text{ITC}} + \mathcal{L}_{\text{ITM}} + \mathcal{L}_{\text{LM}}
$$

## 附录 B 常见误解纠正

| ❌ 误解 | ✅ 正解 |
|---|---|
| BLIP 功能比 CLIP 多,所以碾压 CLIP | 不在同一个位置。CLIP 是**中间件/零件**(被集成一万次),BLIP 是**终点产品**。BLIP-2 自己的视觉塔就是冻结的 CLIP |
| 因为文本看不全,所以用 LM 任务 | 因果方向反了。**任务目标 → 文本是输入还是输出 → 能否看全文 → 用什么 mask**。可见性是结果不是原因 |
| CapFilt 就是「判断网上数据哪些是对的」 | 只说对一半。Filter 是减法(提精度),**Captioner 是加法(提信息量)**,把「图好但文本是 DSC_0472.jpg」的样本救活。数据量可能增加 |
| CapFilt 可以滚雪球不停自举 | BLIP 只滚了**一轮**。多轮成本高、收益递减,且误差累积会导致 **model collapse**。后续做法是换外部老师 |
| Q-Former 是弯路,早该用 MLP | 约束不同最优解不同。**LLM 冻死时桥必须很聪明**。且当时上下文只有 2048,压缩有强现实动机 |
| LLaVA 的贡献是发现 MLP 就够了 | 真正的贡献是 **Visual Instruction Tuning**——用纯文本 GPT-4 造 158K 多模态指令数据。有了数据才敢解冻 LLM,解冻了桥才能变笨 |
| resampler 被淘汰了 | 被淘汰的是「固定数量抽象 query 做剧烈压缩」。视频/多图场景压缩仍是刚需,只是改用不丢空间结构的压法(patch merge) |
| 对比学习 batch 越大越好 | SigLIP 实测 **32k 左右就饱和**,1M 无额外收益。InfoNCE 的 log N 上界 ≠ 实际表征质量 |
| beam search 生成的伪标签质量更高所以更好 | 噪声率确实更低,但**信息增益低**(句式模板化),下游反而更差 |
